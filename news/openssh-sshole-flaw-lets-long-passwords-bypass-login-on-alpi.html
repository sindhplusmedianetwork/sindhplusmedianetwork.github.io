OpenSSH 'SSHole' Flaw Lets Long Passwords Bypass Login on Alpine Linux

SP
By Sindh Plus Media Network
November 08, 2026 · 2 min read
WhatsApp Facebook X

A serious password authentication bypass in OpenSSH, named "SSHole" by researcher Ozgun Kilicten, lets accounts that should never log in with a password be opened on musl-based Linux systems, including Alpine Linux, by sending any password 257 to 1,024 characters long. The flaw carries the identifier CVE-2026-123158 and has been closed in OpenSSH 10.6p2, while Alpine Linux issued an official security advisory on November 5, 2026, urging immediate updates and an sshd restart, and multiple outlets including SecurityWeek, BleepingComputer and Help Net Security covered the details the same day. OpenSSH developer Damien Miller said the root cause lies outside sshd, but exploitation through sshd is possible and this release blocks it.

According to Help Net Security, a threat-intelligence firm observed attacks within less than nine hours of disclosure and confirmed successful root access on an Alpine honeypot, with the observed source IP bypassing authentication with unusually long passwords and running identity commands in non-interactive SSH sessions. The flaw works because accounts whose password field in the shadow file is only an asterisk normally cannot log in with a password, but musl's crypt function returns an asterisk when a password longer than 256 bytes fails, and when the stored field is also an asterisk the comparison succeeds and login is granted. An attack needs password authentication enabled, PAM disabled, at least one asterisk account and at least one local account with a real hash, and Alpine's default OpenSSH server package is built without PAM, so the conditions are often met.

Kilicten ran about 17,600 unusual login tests, and only musl builds without PAM accepted false logins, while glibc systems such as Debian, Ubuntu and Fedora, setups with PAM, Dropbear and OpenBSD were unaffected. Fixed packages are included in Alpine 3.21.10, 3.22.8, 3.23.8 and 3.24.4, with OpenSSH 10.6p2 on Edge, and a package upgrade does not replace the running sshd, so a restart is essential.
